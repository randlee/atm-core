# Template Workflow Metadata

This guide describes optional template metadata for durable, generic workflow
analytics. It does not define an ATM workflow or reserve team-specific words.

## Recommended declaration

```yaml
---
name: dev-task
metadata:
  type: dev-task
  tags:
    - domain:orchestration
    - audience:engineering
  workflow:
    scope:
      kind: sprint
      variable: sprint
    state: dev-start
    stage: dev
    transition: start
    iteration_variable: round
---
```

All `workflow` fields are optional as one declaration, but a partial workflow
object is invalid. `scope.variable` and `iteration_variable`, when present,
refer to required or supplied template variables. ATM resolves them from the
already-merged variables stored with the admitted message.

## Naming conventions

Use lowercase kebab-case identifiers. The recommended state spelling is
`<stage>-<transition>`:

| Purpose | Recommended examples |
| --- | --- |
| stage | `plan`, `dev`, `fix`, `qa`, `release` |
| transition | `start`, `complete`, `blocked`, `approved`, `rejected` |
| state | `dev-start`, `qa-complete`, `fix-start` |
| scope kind | `sprint`, `issue`, `release`, `campaign` |

These names are recommendations, not ATM enums. A project may use a stable
alternative vocabulary; consumers should query the explicit fields rather than
split `state` text.

## Tags and provenance

`metadata.tags` are literal template tags. On same-host decomposed admission,
ATM snapshots them as applied-template tags and separately preserves any
sender-provided instance tags. It also creates an effective tag projection for
fast search. Template changes do not rewrite old messages.

The following prefixes are generated by ATM and must not be supplied by a
template or sender: `template-type:`, `content-format:`, `workflow-state:`,
`workflow-stage:`, `workflow-transition:`, and `workflow-scope-kind:`.

Use ordinary tags for project dimensions such as `phase:an`,
`component:search`, or `audience:engineering`. Do not put secrets or private
payload values in tags: effective tags are search material.

## What is and is not measured

ATM retains workflow facts, it does not schedule work. A generic duration or
OpenTelemetry span projection pairs template-declared states within a declared
scope. For example, a caller may request `dev-start` to `dev-complete` for
`scope.kind=sprint`; ATM has no built-in meaning for either string.

Cross-host and other rendered-plain fallbacks retain their ordinary message
body and sender tags but cannot claim a decomposed template workflow snapshot.
Use the same-host decomposed lane for durable structured analytics.
