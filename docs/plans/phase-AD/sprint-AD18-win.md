## Windows Execution Report

- Date: 2026-07-06

### Windows Findings

- AD.18 implementation was functionally correct on Windows, but several tests
  compared against `std::fs::canonicalize()` expectations. On Windows,
  canonicalization can add the `\\?\` verbatim prefix while
  `command_invocation_dir()` intentionally preserves the process
  `current_dir()` path shape.
- `atm-core` protocol tests expected a logical filesystem socket path even
  though Windows maps the accepted runtime endpoint through its legacy local IPC.
- The `python3` launcher on this host resolves to a Windows Store Python 3.13
  shim without `codespell_lib`; the repo Windows lint path using `python`
  resolves to Python 3.12 with the required lint dependencies.

### Windows Fix

- Adjusted AD.18 test expectations to compare command invocation paths through
  the repo helper contract instead of independent canonicalization.
- Adjusted protocol endpoint tests to compare the logical `ATM_HOME` runtime
  root after platform local-IPC conversion, preserving the legacy endpoint contract
  on Windows.
- Updated smoke artifacts with the AD.18 runtime-root rows generated by the
  passing Windows smoke runs.
