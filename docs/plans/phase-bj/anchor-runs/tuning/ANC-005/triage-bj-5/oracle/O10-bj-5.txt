# bj-5: out-of-band skill integrity manifest; install verification and hand-runnable doctor

## Description

### Goal
For atm-bd-orchestration issue #349: atm-bd's built wheel and sdist carry a manifest of every shipped skill file's sc-sha; `atm-bd skill` verifies the files it installs against that published manifest; a hand-runnable plugin doctor checks an installed copy without atm-core. This is phase-bj work in atm-bd-orchestration, independent of bj-1 through bj-4. Anchors: ANC-087, ANC-088, ANC-003, ANC-010, ANC-011, ANC-012. No SHA is written into any source file; hashing is the `sc-sha` package's `sc_sha` module; the sc-publish kit (`.github/scripts`, `.github/actions`) is unchanged.

### Deliverables
1. `apps/atm-bd-console/hatch_build.py`: in `_include_skills`, after choosing the bundled skill tree, write `skill-manifest.json` (schema version, atm-bd version, one `{path, sc_sha}` per shipped file of the plugin tree in sorted path order, and `sc_sha.calculate_composition_hash` over them) into the build output and force-include it beside the bundled skills in both the wheel and the sdist. This is the published manifest: it exists only in the built artifacts that sc-publish uploads, never in git.
2. `apps/atm-bd-console/pyproject.toml` and `uv.lock`: add `sc-sha>=1.7.0,<2` to the runtime dependencies and to the build-system requires, so `import sc_sha` works in the build and in an installed atm-bd. `sc_sha.calculate_hash` is the per-file hash; no other hasher is written.
3. `apps/atm-bd-console/src/atm_bd_console/skill_integrity.py` (new): `load_manifest(source)`, `verify_tree(pkg_dir, manifest) -> list[PathResult]` with `ok|modified|missing|extra`, and `write_install_record(dest, version, commit, manifest, installed)`. Sources of the published manifest: bare `atm-bd skill` reads the one packaged in the installed wheel (no network, ANC-010); `atm-bd skill x.y.z` reads the manifest from the published atm-bd x.y.z sdist on PyPI (`https://pypi.org/pypi/atm-bd/<x.y.z>/json`), and `--latest` does the same for the newest published version on PyPI, whose tag `v<version>` it installs (ANC-012 v3).
4. `apps/atm-bd-console/src/atm_bd_console/skill_source.py`: `--latest` resolves the newest published version on PyPI and clones its `v<version>` tag instead of `main`; bare keeps the packaged files (ANC-010) and `x.y.z` keeps cloning the `vX.Y.Z` tag of atm-bd-orchestration (ANC-011).
5. `apps/atm-bd-console/src/atm_bd_console/skill.py`: inside the existing `with skill_source.resolve_source(...)` block, call `verify_tree(source.pkg_dir, manifest)` before `installer.plan_install`; any `modified` or `missing` path stops the install before any write, prints one `<status> <path>` line per path and returns exit 1. After `installer.apply_plan`, call `write_install_record` with the version, commit and the sc-sha of each file as installed (rendered team, prefix and member values make installed bytes differ from published bytes by design). The `installed ... from <ref> @ <commit> (atm-bd <version>)` line is unchanged (ANC-003). The plugin `install.py` (bj-1's fence) is called as today and not edited.
6. `plugins/atm-bd-orchestration/skills/atm-bd-orchestration/scripts/atm-hook-doctor.py` (new): reads the install record in the target `.claude` (or `.codex`) directory, hashes each recorded installed file with `sc_sha.calculate_hash`, prints one `ok|modified|missing|extra` line per path and `PASS` or `FAIL`; exposes the same check as `doctor(dest) -> Result` for phase-bk's `hook.doctor()`. It imports nothing from atm-core or atm_bd_console; when `sc_sha` is missing it exits 2 with the fix `uv pip install 'sc-sha>=1.7.0,<2'`.
7. `manifest.yaml`: regenerate its generated block with `tests/gen_manifest.py` so the doctor script ships; this sprint never hand-edits the block (Ownership below).
8. Tests (deterministic fixture trees, controlled file contents, injected PyPI/git responses, no sleeps): manifest coverage and aggregate, verification pass and refusal for bare, `x.y.z` and `--latest`, install-record contents, doctor outcomes, and the built wheel and sdist each containing `skill-manifest.json`.

### Ownership
`manifest.yaml`'s artifact block is generated by `tests/gen_manifest.py` from the files present. bj-3 and bj-5 both add shipped files, so each regenerates the block in its own layer and never hand-edits it; at the later layer's rebase the block is regenerated again, which is the conflict resolution. No sprint writes the block by hand.

### Does Not Close
- Phase-bk's atm-core registration of `hook.doctor()`; this sprint exposes the plugin callable only.
- Any SHA inside a shipped or source file, a second hasher, or a change to the sc-publish kit.
- Edits to bj-1's `install.py`.

## Acceptance criteria

### Acceptance Criteria
- [ ] (ANC-087) `uv build` in `apps/atm-bd-console` produces a wheel and an sdist that each contain `skill-manifest.json` with exactly one entry per shipped plugin file and the composition aggregate; changing one plugin file changes its entry and the aggregate (test over the built artifacts).
- [ ] (ANC-088) `atm-bd skill`, `atm-bd skill x.y.z` and `atm-bd skill --latest`, run through `atm_bd_console.cli` with injected PyPI and git responses, install when every file matches and exit 1 before any write when a file is modified or missing, printing each affected path.
- [ ] (ANC-012) `atm-bd skill --latest` clones `v<newest PyPI version>`, not `main`; (ANC-010) bare `atm-bd skill` verifies with the network disabled; (ANC-003) every install prints the ref, commit and app version line unchanged.
- [ ] The install record lists the version, commit and each installed file's sc-sha; the doctor reads it and reports `ok` for an untouched install, `modified`, `missing` and `extra` for the three planted changes, and both `PASS` and `FAIL` aggregates.
- [ ] `atm-hook-doctor.py` runs with `python3` and no atm-core or atm_bd_console import (test imports it in an isolated environment with only `sc_sha`); with `sc_sha` absent it exits 2 naming the install command.
- [ ] `rg -n "hashlib|sha256\(" apps/atm-bd-console/src/atm_bd_console/skill_integrity.py plugins/atm-bd-orchestration/skills/atm-bd-orchestration/scripts/atm-hook-doctor.py` finds nothing; `git diff integrate/phase-bj -- .github plugins/atm-bd-orchestration/install.py` is empty.
- [ ] `tests/gen_manifest.py --check` passes on the layer.
