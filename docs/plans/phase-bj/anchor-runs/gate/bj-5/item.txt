# bj-5: skill integrity manifest; install verification and hand-runnable doctor

## Description

### Goal
For atm-bd-orchestration issue #349: atm-bd's built wheel and sdist carry a manifest of every shipped skill file's sc-sha; `atm-bd skill` verifies the files it installs against that published manifest; a hand-runnable plugin doctor checks an installed copy without atm-core. The manifest detects skill files that differ from what was published (a tag clone, a bundled tree or an installed copy changed after release); it is not a signature and does not defend a tampered artifact. This is phase-bj work in atm-bd-orchestration, independent of bj-1 through bj-4. Anchors: ANC-087, ANC-088, ANC-003, ANC-010, ANC-011, ANC-012. No SHA is written into any source file; hashing is the `sc-sha` package's `sc_sha` module; the sc-publish kit (`.github/scripts`, `.github/actions`) is unchanged.

### Deliverables
1. `apps/atm-bd-console/hatch_build.py`: in `_include_skills`, after choosing the bundled skill tree, write `skill-manifest.json` (schema version, atm-bd version, one `{path, sc_sha}` per shipped file in sorted path order, where the shipped set is every file of the bundled skill tree except `__pycache__/` and `*.pyc` (installers byte-compile into the package), and `sc_sha.calculate_composition_hash` over them) into the build output and force-include it beside the bundled skills in both the wheel and the sdist. This is the published manifest: it exists only in the built artifacts that sc-publish uploads, never in git.
2. `apps/atm-bd-console/pyproject.toml` and `uv.lock`: add `sc-sha>=1.7.0,<2` to the runtime dependencies and to the build-system requires, so `import sc_sha` works in the build and in an installed atm-bd. `sc_sha.calculate_hash` is the per-file hash; no other hasher is written.
3. `apps/atm-bd-console/src/atm_bd_console/skill_integrity.py` (new): `load_manifest(source)`, `verify_tree(pkg_dir, manifest) -> list[PathResult]` with `ok|modified|missing|extra` (`extra` = a file of the shipped set under `pkg_dir` that the manifest does not list), and `write_install_record(dest, version, commit, manifest, installed)`. Sources of the published manifest: bare `atm-bd skill` reads the one packaged in the installed wheel (no network, ANC-010); `atm-bd skill x.y.z` reads it from the `atm_bd-<x.y.z>.tar.gz` asset of the repository's `v<x.y.z>` GitHub release, and `--latest` reads it from the same asset of the repository's latest published release (`releases/latest`, tag `v<version>`), whose tag it installs (ANC-012). Fail-closed: when the release, its sdist or the sdist's `skill-manifest.json` is absent (every release before the first one this sprint's build publishes), or the bundled tree has no manifest, the install stops before any write with exit 1 and `atm-bd skill: <ref> has no published skill-manifest.json; cannot verify`.
4. `apps/atm-bd-console/src/atm_bd_console/skill_source.py`: `--latest` resolves the repository's latest published release and clones its `v<version>` tag instead of `main`; bare keeps the packaged files (ANC-010) and `x.y.z` keeps cloning the `vX.Y.Z` tag of atm-bd-orchestration (ANC-011).
5. `apps/atm-bd-console/src/atm_bd_console/skill.py`: inside the existing `with skill_source.resolve_source(...)` block, call `verify_tree(source.pkg_dir, manifest)` before `installer.plan_install`; any `modified`, `missing` or `extra` path stops the install before any write, prints one `<status> <path>` line per path and returns exit 1. After `installer.apply_plan`, call `write_install_record` with the version, commit and the sc-sha of each file as installed (rendered team, prefix and member values make installed bytes differ from published bytes by design). The `installed ... from <ref> @ <commit> (atm-bd <version>)` line is unchanged (ANC-003); the `--latest` help reads `install the latest published release`. The plugin `install.py` (bj-1's fence) is called as today and not edited.
6. `plugins/atm-bd-orchestration/skills/atm-bd-orchestration/scripts/atm-hook-doctor.py` (new): reads the install record in the target `.claude` (or `.codex`) directory, hashes each recorded installed file with `sc_sha.calculate_hash`, prints one `ok|modified|missing|extra` line per path and `PASS` or `FAIL` (`extra` = a file inside a `skills/<name>/` directory the record lists files for that the record does not list; shared directories such as `agents/` are not scanned). Fail-closed: with no install record (an `install.py` install writes none) it prints `missing atm-bd-install.json` and `FAIL`, exit 1; run as `python3 atm-hook-doctor.py doctor`, it reads `{"schema_version", "hook": "doctor", "team", "phase", "custom"}` on stdin, resolves its install folder from its own path, runs the same manifest check through `doctor(request: dict) -> dict` and prints exactly `{"success", "message", "findings": [{"severity", "code", "message", "remediation"}]}` (atm-core #1877, ADR-068 D6 doctor contract, no other keys): `success` false and one `error` finding per modified, missing or extra path (codes `skill_file_modified|skill_file_missing|skill_file_extra`) or one `install_record_missing` finding, `remediation` the `atm-bd skill` reinstall command; without the subcommand it stays the manual CLI. It imports nothing from atm-core or atm_bd_console; when `sc_sha` is missing it exits 2 with the fix `uv pip install 'sc-sha>=1.7.0,<2'`; in `doctor` mode it still prints the contract reply first, `success` false with one `sc_sha_missing` error finding carrying that fix as `remediation`.
7. `manifest.yaml`: regenerate its generated block with `tests/gen_manifest.py` so the doctor script ships; this sprint never hand-edits the block (Ownership below).
8. Tests (deterministic fixture trees, controlled file contents, injected GitHub release/git responses, no sleeps): manifest coverage and aggregate, verification pass and refusal for bare, `x.y.z` and `--latest`, refusal for a release without a manifest, install-record contents, doctor outcomes, and the built wheel and sdist each containing `skill-manifest.json`.

### Ownership
`manifest.yaml`'s artifact block is generated by `tests/gen_manifest.py` from the files present. bj-3 and bj-5 both add shipped files, so each regenerates the block in its own layer and never hand-edits it; at the later layer's rebase the block is regenerated again, which is the conflict resolution. No sprint writes the block by hand.

### Does Not Close
- Phase-bk's atm-core side that runs `atm-hook-doctor.py doctor` from atm doctor; this sprint ships the plugin side only.
- Any SHA inside a shipped or source file, a second hasher, or a change to the sc-publish kit.
- Edits to bj-1's `install.py`.

## Acceptance criteria

### Acceptance Criteria
- [ ] (ANC-087) `uv build` in `apps/atm-bd-console` produces a wheel and an sdist that each contain `skill-manifest.json` with exactly one entry per shipped plugin file and the composition aggregate; changing one plugin file changes its entry and the aggregate (test over the built artifacts); `sc-sha>=1.7.0,<2` is in `[project].dependencies` and `[build-system].requires` and `uv lock --check` passes.
- [ ] (ANC-088) `atm-bd skill`, `atm-bd skill x.y.z` and `atm-bd skill --latest`, run through `atm_bd_console.cli` with injected GitHub release and git responses, install when every file matches and exit 1 before any write when a file is modified, missing or extra, printing each affected path, or when the release has no `skill-manifest.json` (`tests/test_skill_integrity.py`).
- [ ] (ANC-012) `atm-bd skill --latest` clones the tag of the repository's latest published release, not `main`; (ANC-010) bare `atm-bd skill` verifies with the network disabled; (ANC-003) every install prints the ref, commit and app version line unchanged.
- [ ] The install record lists the version, commit and each installed file's sc-sha; the doctor reads it and reports `ok` for an untouched install, `modified`, `missing` and `extra` for the three planted changes, and both `PASS` and `FAIL` aggregates; with no `atm-bd-install.json` it reports `missing atm-bd-install.json`, `FAIL`, exit 1, and in `doctor` mode `success` false with one `install_record_missing` finding (`scripts/tests/test_atm_hook_doctor.py`).
- [ ] `atm-hook-doctor.py` runs with `python3` and no atm-core or atm_bd_console import (test imports it in an isolated environment with only `sc_sha`); with `sc_sha` absent it exits 2 naming the install command, and in `doctor` mode prints `success` false with one `sc_sha_missing` finding.
- [ ] `atm-hook-doctor.py doctor` with `{"schema_version":"1.0.0","hook":"doctor","team":"atm-dev","phase":"bj","custom":{}}` on stdin, run from a copied install folder, prints only the keys `success`, `message`, `findings`: `success` true and no error finding for the untouched copy; `success` false and one `error` finding naming the path for a modified file.
- [ ] `tests/gen_manifest.py --check` passes on the layer.
