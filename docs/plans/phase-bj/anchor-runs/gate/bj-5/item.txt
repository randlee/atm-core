# bj-5: out-of-band skill integrity manifest; install verification and hand-runnable doctor

## Description

### Goal
For atm-bd-orchestration issue #349, publish an out-of-band sc-sha manifest for every file shipped by the skill, verify those files before `atm-bd skill` installs a selected tag or `--latest`, and provide a plugin doctor usable without atm-core. This is phase-bj work in atm-bd-orchestration, independent of bj-1 through bj-4. Anchors: ANC-075..077. The integrity manifest is generated into the package release artifact; no file contains an embedded SHA. Hashing uses only the Python sc-sha implementation shipped by sc-compose; no second hasher is added. The sc-publish kit is unchanged.

### Deliverables
1. `skills/atm-bd-orchestration/scripts/publish-skill-manifest.py`: package script called by the existing package publish flow; enumerate all shipped agents, skills, Python files, templates, and scripts; compute sc-sha per path with sc-compose's Python implementation; write path/hash entries and the composition aggregate into the release artifact. This does not modify the sc-publish kit.
2. `atm-bd skill` installer entry point (`skills/atm-beads/scripts/atm-bd-skill` and `skill-install.py`): for the selected release tag or `--latest`, verify each downloaded file against that release's published manifest before the installer renders any team, prefix or member value into it (the manifest covers the files as published); refuse mismatches and list the affected paths. After rendering, persist the version and the sha of each file as installed in the install record next to the installed files; doctor checks that record, because a rendered file's installed bytes differ from its published bytes by design.
3. `skills/atm-bd-orchestration/scripts/atm-hook-doctor.py`: hand-runnable plugin command using the same verifier as `hook.doctor()`; report every file as `ok`, `modified`, `missing`, or `extra`, and aggregate `PASS`/`FAIL`. Keep the check in the plugin so phase-bj can run it without atm-core; phase-bk registration delegates to this same function.
4. Test manifest coverage and stable sc-sha parity, install pass/refusal behavior for a tag and `--latest`, and doctor statuses/aggregate using deterministic fixture trees and controlled file contents. Never write hashes into source files; do not introduce a second hashing implementation.

### Required Work
- Scope source: Rand's atm-bd-orchestration issue #349 and its comments; no additional implementation scope is implied.
- `requirements` and `adrs` are `NONE`: the governing specification is issue #349, and atm-core phase-bk's future hook registration is a caller only.
- Preserve bj-3's ownership of `manifest.yaml`; this sprint owns the separate release integrity manifest and does not change the sc-publish kit.

### Does Not Close
- Phase-bk changes in atm-core that register `hook.doctor()`; this sprint exposes the plugin-side callable only.
- Any embedded SHA header, hash inside a shipped file, or second hasher.
- Changes to sc-publish.

## Acceptance criteria

### Acceptance Criteria
- [ ] (ANC-075) A strict package build creates a release artifact manifest with exactly one sc-sha entry for every shipped agent, skill, Python file, template, and script, and the aggregate equals the sorted-path composition hash; a changed shipped file changes its manifest entry.
- [ ] The publish script calls the sc-compose Python sc-sha implementation and matches sc-sha's UTF-8, line-ending normalization, BOM, lowercase hex, and aggregate behavior; no SHA value is embedded in any source file and no second hasher is implemented. sc-publish files and behavior are unchanged.
- [ ] (ANC-076) `atm-bd skill <tag>` and `atm-bd skill --latest` install a matching artifact; a modified or missing file makes each command fail before install completion and names each affected path. Extra installed files are surfaced by doctor.
- [ ] Install records persist the selected version and the exact published manifest used. The doctor reads this install record rather than recomputing an expected manifest from the current package checkout.
- [ ] (ANC-077) Hand-running `python3 plugins/atm-bd-orchestration/skills/atm-bd-orchestration/scripts/atm-hook-doctor.py` emits one `ok|modified|missing|extra` result per fixture path and aggregate `PASS|FAIL`; both aggregate outcomes are covered.
- [ ] The verifier function called by the script is the same callable exposed as `hook.doctor()` when phase bk registers it; the plugin check has no atm-core dependency.
- [ ] Tests use deterministic fixture files and explicit expected contents/paths; no sleeps, races, timing thresholds, or event-loop ordering.

### Validation
- Strict-render the package and manifest inputs, then run focused integrity-manifest, install-verification, and doctor tests in the atm-bd-orchestration worktree.
- Verify no in-file hashes and no sc-publish changes in the PR diff.
