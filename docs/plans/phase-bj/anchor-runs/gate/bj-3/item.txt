# bj-3: sanity-stack subagent and dev-sanity PASS wiring: sequential spawns, lock timeout, lean mode

## Description

### Goal
On a sanity PASS the sanity side links the checked PR as the new top of the phase stack under the stack bead's claim before the close hook runs; when more than one sanity task is open, or its own inline link failed, dev-sanity spawns the `sanity-stack` subagent, one spawn at a time in verdict order, each handling exactly one next-top layer. The race is the subagent's job: first PASS wins the top, the other dev gets `rebase-required` with no round counted; a lock timeout returns the holder and never blocks the team or escalates to a person. Governing text: `docs/requirements/sanity-stack.md` 1 to 13, `dev-sanity.md` 9, 10, 11, 13, 28, 29, 32, `team-lead.md` 22, 42, 43. Anchors: ANC-065, 066, 067, 068, 069, 071, 074.

### Prerequisites (what this sprint consumes)
- bj-1 delivers `atm-task-close.py --role sanity`, which refuses a PASS close without a stack result in the vars (`stacked` with the new top and `stack_number`) and sends `rebase-required.xml.j2`; this sprint's procedures end by running that hook with that result (ANC-055, ANC-065).
- bj-2 delivers the stack bead `<prefix>-phase-<x>.stack` with `metadata.trunk`, `stack_number` and `layers` of `{branch, pr, head, base, linked}` validated by `bead_schema.py`; this sprint writes `layers` under the bead's claim (ANC-067).

### Deliverables
1. `agents/sanity-stack.md`: a subagent of dev-sanity (tools Bash, Read), one next-top layer per spawn. Input, one fenced JSON object: `checked_bead`, `branch`, `pr_number`, `commit`, `stack_bead`, `budget` (`full` or `lean`), `timeout_s` (default 60). Procedure: claim the stack bead with `bd update <stack bead> --claim`, retrying every 5 s until `timeout_s`; under the lock and in this order with nothing between: re-read `layers` from the bead (never from the input), `git fetch origin`, choose the current top branch or `trunk` when the ledger is empty, then verify that baseline is an ancestor of `commit`; `full`: link every `linked: false` layer in order then this PR as the new top (`gh stack link <stack_number> <pr>`; the first stack from layers 0 and 1 with `--base <trunk>`), one `/sc-gh-stack-view`; `lean`: the ancestor check above is the only divergence check; append the first empty-ledger PASS as a singleton with base trunk, and preserve all unlinked entries during later catch-up; verify the PR base ref equals the top branch from one filtered REST pull list (`gh api repos/<o>/<r>/pulls?state=open&per_page=100 --jq` to number, base, head, sha, draft; never the raw body) and record `linked: false`; append the layer; write the metadata with `bd update --metadata @file.json`; release with `bd update <stack bead> --if-assignee "$ATM_IDENTITY" --status open --assignee ""`. Output, one fenced JSON object: `stacked` (new top, nullable `stack_number` for an initial singleton), `rebase_required`, `lock_timeout` (holder, claim time, holder's active task from `atm task list`) or `stack_failed`, with the evidence. GraphQL unavailable is detected and forces `lean`; a lean run makes no GraphQL call (ANC-069). Ancestor check fails: `rebase_required`, link nothing, write nothing (ANC-065). A link that fails for a stack reason is repaired with the `sc-gh-stack` recipes within this one layer, never rewriting a layer with children; unrecoverable: `stack_failed`, lock released, ledger unchanged. Under the lock, reconcile the hosted chain against existing ledger entries without replacing the ledger: preserve every `linked:false` entry; mark only proven links as linked; record hosted-only partial results only when uniquely attributable; ambiguity or conflicting ancestry returns `stack_failed` without ledger mutation. There is no automatic reclaim: a claim still held at `timeout_s` returns `lock_timeout`, and only the lead releases a stuck claim, by hand. The metadata commit and the release are both `bd update <stack bead> --if-assignee "$ATM_IDENTITY"`; a mismatch (exit 13) leaves the ledger unchanged. dev-sanity waits for each spawn's result before the next, so no second writer of the same identity exists; never call `bd reclaim` or infer lease expiry from bead event age. The agent never refuses the task, never sends the dev a FAIL, never escalates to a person (ANC-068).
2. `agents/dev-sanity.md` PASS path (dev-sanity 28, sanity-stack.md 12, 13): one sanity task open: dev-sanity runs the procedure of deliverable 1 itself, inline, same order, same lock; more than one open, or its own inline link failed: it spawns `sanity-stack`, one spawn at a time in verdict order, never two in flight (ANC-066). `stacked`: run `atm-task-close.py --role sanity` with the stack result in the vars. A `not_reproducible` fix has no new PR: dev-sanity verifies the cited `file:line` at the commit and branch the assignment names (the current stack top, deliverable 4 of bj-1), spawns no `sanity-stack`, links nothing, and closes PASS with `outcome: not_reproducible` and no stack result. `rebase_required`: reopen the checked bead to the dev, send `rebase-required.xml.j2` on the dev's open task, leave `sanity_round` unchanged, keep the PASS in the ledger, close nothing (ANC-071). `lock_timeout`: keep the sanity task active, send the holder one plain message asking for the release, continue other sanity checks, re-spawn after the holder's reply or after another `timeout_s`; never refuse, never FAIL the dev, never a person (ANC-068). `stack_failed`: report to the lead as stack owner with the evidence and keep the task active (team-lead 22). `budget` is `lean` when GraphQL is unavailable or the agent is watching its token budget.
3. `agents/dev-sanity.md` items 9 and 10 (ANC-084..086): the dev-sanity coordinator makes one Jev client call and does not add a second retry loop; the bj-4-owned Jev client defines and tests its bounded transport retry policy; an oversized context is shortened and the call retried by that client, never returned to dev-sanity as a failure; the failure reason is the verbatim error, kept in the run's ledger row as kind `API_FAILURE`, never a FAIL verdict; every fallback use is logged with its verbatim error and said once in the close report. The LLM subagent spawn is fenced by a start and end timer whose elapsed is written as `llm_elapsed_s` to the ledger row. No class bead, outage bead, hold on re-dispatch, refusal citation or checker-defect side channel appears anywhere in the agent text.
4. `manifest.yaml` ships `agents/sanity-stack.md`; `install.py` copies it like the other agents without a code change. The generated block is written only by `tests/gen_manifest.py`, never by hand; bj-5 runs the same generator for its files, and the later of the two layers regenerates it at rebase so `gen_manifest.py --check` passes on the stack top.
5. `CHANGELOG.md`: the phase entry for bj-1, bj-2 and bj-3 (close hook, stack bead and pour, sanity-stack), written here because this sprint lands after both.
6. Tests, `scripts/tests/test_agent_prompts.py`: the agent files contain the required phrases and none of the forbidden ones: `rg -n "class bead|outage bead|hold on re-dispatch|citation|checker-defect" agents` returns nothing; `sanity-stack.md` names `timeout_s`, `budget`, `lock_timeout`, `rebase_required`, `stack_failed`, `--claim`, `--if-assignee`; `dev-sanity.md` forbids a second spawn while one is in flight.

### This Sprint Does Not Close
- The hook itself and the templates (bj-1); the stack bead schema and pour (bj-2); the console tabs and the ledger producers (bj-4).
- The lead's stack recipes (unstack, restack, land under the claim): the `sc-gh-stack` skill and `team-lead.md` 42 already state them; no script is added.

### Recovery and Retry
Recovery is driven by injected clock and command responses. It preserves ledger-only unlinked lean entries, reconciles only uniquely attributable hosted link events, and fails closed on ambiguity. Every metadata commit is guarded by `--if-assignee "$ATM_IDENTITY"`; there is no automatic reclaim. Jev retries are owned by bj-4 at the actual HTTP client boundary; dev-sanity makes one call and records the returned API_FAILURE without coordinator retry multiplication.
