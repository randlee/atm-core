# bj-3: sanity-stack subagent and dev-sanity PASS wiring: sequential spawns, lock timeout, lean mode

## Description

### Goal
On a sanity PASS the sanity side links the checked PR as the new top of the phase stack under the stack bead's claim before the close hook runs; when more than one sanity task is open, or its own inline link failed, dev-sanity spawns the `sanity-stack` subagent, one spawn at a time in verdict order, each handling exactly one next-top layer. The race is the subagent's job: first PASS wins the top, the other dev gets `rebase-required` with no round counted; a lock timeout returns the holder and never blocks the team or escalates to a person. The link commands live in one script, `scripts/sanity-stack-link`, which dev-sanity runs inline and the subagent runs and repairs around, so the race, the lock and lean mode are code under test. This sprint is the top layer (pr_target `sprint/bj-4-runs-tabs`, closure integration): its harness runs the link and bj-1's close hook as landed. Governing text: `docs/requirements/sanity-stack.md` 1 to 13, `dev-sanity.md` 9, 10, 11, 13, 28, 29, 32, `team-lead.md` 22, 42, 43. Anchors: ANC-065, 066, 067, 068, 069, 071, 084, 086.

### Deliverables
1. `scripts/sanity-stack-link` (new; fixed argv `sanity-stack-link --input <file.json>`, one JSON result on stdout; bd, git, gh and atm through an injectable runner and the clock injectable, as in `atm-task-close.py`): the one owner of the link procedure (sanity-stack.md 2, 4 to 10). Input: `checked_bead`, `branch`, `pr_number`, `commit`, `stack_bead`, `budget` (`full` or `lean`), `timeout_s` (default 60). Claim with `bd update <stack bead> --claim`, retrying every 5 s until `timeout_s` (900 s lease kept by `bd heartbeat`); a claim of THIS stack bead whose lease expired more than 1800 s ago is abandoned and recovered only with `bd reclaim --id <stack bead> --older-than 1800s`, then `layers` is re-derived as below and the result carries `reclaimed` (former holder, claim time); unscoped `bd reclaim` and event age as expiry are never used. A live claim still held at `timeout_s` returns `lock_timeout` (holder, claim time, holder's active task from `atm task list`). Under the lock, in this order with nothing between: re-read `layers` from the bead (never from the input), `git fetch origin`, take the current top branch or `trunk` when the ledger is empty, verify that baseline is an ancestor of `commit`; `full`: link every `linked: false` layer in order then this PR as the new top (`gh stack link <stack_number> <pr>`; the first stack from layers 0 and 1 with `--base <trunk>`), one `/sc-gh-stack-view`; `lean`: the ancestor check is the only divergence check; verify the PR base ref equals the top branch from one filtered REST pull list (`gh api repos/<o>/<r>/pulls?state=open&per_page=100 --jq` to number, base, head, sha, draft; never the raw body) and record `linked: false`; append the first empty-ledger PASS as a singleton with base trunk; append the layer; write the metadata with `bd update --if-assignee "$ATM_IDENTITY" --metadata @file.json` (the commit point); release with `bd update <stack bead> --if-assignee "$ATM_IDENTITY" --status open --assignee ""`. Results: `stacked` (new top, nullable `stack_number` for an initial singleton), `rebase_required`, `lock_timeout` or `stack_failed`, each with evidence. GraphQL unavailable is detected and forces `lean`; a lean run makes no GraphQL call (ANC-069). Ancestor check fails: `rebase_required`, link nothing, write nothing (ANC-065). Reconcile under the lock, before anything else, when the bead and the hosted chain disagree (a torn link, a reclaimed claim): preserve every `linked: false` entry, mark only proven links linked, record hosted-only results only when uniquely attributable; ambiguity, conflicting ancestry, a failed link, or exit 13 on any `--if-assignee` write returns `stack_failed` with the lock released (when held) and the ledger unchanged.
2. `agents/sanity-stack.md`: a subagent of dev-sanity (tools Bash, Read), one next-top layer per spawn, input the same fenced JSON object. It runs `sanity-stack-link`; on `stack_failed` for a stack reason (stale local tracking, a stack number minted anew, a PR retargeted or closed, a non-linear stack) it claims the stack bead with the same timeout, repairs with the `sc-gh-stack` recipes within this one layer, never rewriting a layer with children, releases, and runs the script once more. It returns the script's result unchanged as one fenced JSON object; unrecoverable stays `stack_failed`, lock released, ledger unchanged. It makes no `atm` write, never refuses the task, never sends the dev a FAIL, never escalates to a person (ANC-068).
3. `agents/dev-sanity.md` PASS and FAIL paths (dev-sanity 13, 28, 29, 32; sanity-stack.md 11 to 13): one sanity task open: dev-sanity runs `sanity-stack-link` itself; more than one open, or its inline run returned `stack_failed`: it spawns `sanity-stack`, one spawn at a time in verdict order, never two in flight, waiting for each result before the next, so no second writer of the same identity exists (ANC-066). `stacked`: run `atm-task-close.py --role sanity` with the stack result in the vars. A `not_reproducible` fix has no new PR: dev-sanity verifies the cited `file:line` at the commit and branch the assignment names (the current stack top as bj-1 deliverable 4 defines it), runs no link, and closes PASS with `outcome: not_reproducible` and no stack result, which bj-1 deliverable 6 accepts. `rebase_required`, and a pre-claim `sanity-split` `COMMIT_MISMATCH` (dev-sanity 13): reopen the checked bead to the dev, send `rebase-required.xml.j2` on the dev's open task, leave `sanity_round` unchanged, keep the PASS in the ledger, close nothing (ANC-071). `lock_timeout`: keep the sanity task active, send the holder one plain message asking for the release, continue other sanity checks, re-spawn after the holder's reply or after another `timeout_s`; never refuse, never FAIL the dev, never a person (ANC-068). A result carrying `reclaimed` is told to the lead in one plain message. `stack_failed` from the subagent: dev-sanity reports it to the lead as stack owner with the evidence and keeps the task active until the lead says to re-run the link (team-lead 22). FAIL: the close hook with verdict FAIL and the selected undone deliverables with their reasons; the round counter and the cap are the hook's (bj-1 deliverable 6, task-close-hook.md 16); the `sanity-create-findings` FAIL text is removed. The "after a dev-fix" wording (bj-2 deletes `dev-fix.xml.j2`) becomes "after a sanity FAIL reopened the bead" (task-close-hook.md 15). `budget` is `lean` when GraphQL is unavailable or the agent is watching its token budget.
4. `agents/dev-sanity.md` items 9 and 10 (ANC-084, ANC-086): one Jev client call per JEV slot; Jev retries, an API-busy answer retried up to three times, belong to bj-4's `jev_client.py`; an `sc-sanity-llm` spawn that fails with an API error is re-spawned up to three times before that slot reports failure (dev-sanity 9). The failure reason is the verbatim error, kept in the run's ledger row (bj-4's row fields) as kind `API_FAILURE`, never a FAIL verdict; every fallback use is logged with its verbatim error and said once in the close report. The LLM spawn is fenced by a start and end timer whose elapsed is written as `llm_elapsed_s` to the ledger row. The Mandatory Console Report section and its `sanity-run-table.md.j2` render are removed (bj-4 deletes the template; its Sanity tab replaces the table). No class bead, outage bead, hold on re-dispatch, refusal citation or checker-defect side channel appears anywhere in the agent text.
5. `manifest.yaml` ships `agents/sanity-stack.md` and `scripts/sanity-stack-link`; the generated block is regenerated with `tests/gen_manifest.py` in this layer and again after rebase, never hand-merged; `install.py` copies them like the other agents and scripts without a code change.
6. `CHANGELOG.md`: the phase entry for bj-1 to bj-5, written here because this sprint is the top layer.
7. Tests: `scripts/tests/test_agent_prompts.py`, the phrase test of the two prompts (deliverables 2 to 4); `scripts/tests/test_sanity_stack.py`, the scratch end-to-end harness this sprint owns: a scratch git repository with an `origin`, one in-memory bd/gh/atm state behind the injected runner, a controlled clock, driving `sanity-stack-link` and then bj-1's `atm-task-close.py --role sanity` as landed. No live bd, gh, GitHub or ATM, no sleeps.

### Required Work
- Prompt text is minimal: a procedure, not an essay; the link procedure is stated once, in the script.

### This Sprint Does Not Close
- The lead's stack recipes (unstack, restack, land under the claim): the `sc-gh-stack` skill and `team-lead.md` 42 already state them; no script is added for them.

### Recovery and Retry
Recovery is `sanity-stack-link` code driven in `test_sanity_stack.py` by injected clock and runner responses: scoped reclaim of an abandoned claim, re-derived `layers`, preserved ledger-only unlinked lean entries, uniquely attributable hosted links only, fail closed on ambiguity and on exit 13.
