# bj-4: console sanity and quality runs tabs; measured elapsed and dev identity in the sanity ledger

## Description

### Goal
`atm-bd console` shows a sanity runs tab and a quality runs tab, newest run on top, so the runs are seen without asking the agent (Rand: "it is the only thing I want to see from sanity agent"). Elapsed is measured, not derived: the Jev client returns it with every call and dev-sanity's LLM spawn is timed; the dev whose work was checked is a column with name and nerd icon; a Jev API failure after the client-owned bounded policy is its own kind with its own icon, distinct from a JEV FAIL verdict, and its reason shows in the severity table. Governing text: atm-bd-orchestration #347 (Rand's words verbatim and the data contract in its comments), `dev-sanity.md` 9, 10, 46. Anchors: ANC-073 (runs pages), ANC-084 (Jev retries), ANC-052, ANC-060, ANC-061 (dispatch), ANC-051, ANC-017, ANC-019 to ANC-026 (icons), ANC-041, ANC-022.

### Deliverables
1. Sanity ledger row (producers): `jev_client.py` returns `elapsed_s` with every call result; `templates/sanity-run-record.json.j2` and `sanity-run-history` add `dev` (the checked bead's assignee, its ATM identity), `jev_elapsed_s`, `llm_elapsed_s` and `kind` (`verdict` or `API_FAILURE`, with the verbatim error in `error`) to the row; `sanity-run-history` keeps its rule that an identical retry is a no-op and a differing duplicate fails (dev-sanity 46). Rows written before this change read with the new fields absent.
2. `templates/sanity-run-table.md.j2` and `examples/sanity-run-table-vars.json` deleted with the table tests in `scripts/tests/test_sanity_run_history.py`; the `registry.yaml` render block and the `manifest.yaml` generated block are regenerated by `tests/gen_manifest.py`, never hand-edited; `config/legacy-owned.json` is the frozen pre-0.4.0 hash set and is not edited. The runs tab replaces the table in dev-sanity's chat reply (#347); removing dev-sanity's table instruction is bj-3's.
3. `runs.py`: reads the phase sanity ledger rows and, for the quality tab, QA beads of the phase (`bd list -l phase-<x>,stage:qa -n 0 --json`, never `--all`) and linked findings. It displays only data the bj producer writes; no per-reviewer verdict/findings metadata is claimed or required in this phase. Pure functions over the rows, no GitHub call.
4. Sanity tab (`app.py` `TabPane("Sanity", id="sanity")`): one line per run, newest on top: completed time, sprint, PR, dev (icon immediately left of the name per ANC-023, chosen by ANC-024/025), JEV verdict icon and elapsed, LLM verdict icon and elapsed, final verdict, iteration; a run of kind `API_FAILURE` draws the API_FAILURE icon in that reviewer's cell; the severity table below the list has one row per `API_FAILURE` ledger row: sprint, iteration, reviewer (icon and name), the API_FAILURE icon and the row's `error` verbatim.
5. Quality tab (`TabPane("Quality", id="quality")`): two horizontal panes, top about 60 %: QA runs newest first (completed time, sprint, bead, PR, round, verdict, blocking/important/minor counts, elapsed). Selecting a run fills the bottom pane with that run's findings (the finding beads whose `discovered-from` is the QA bead), rendered as markdown by `templates/qa-findings.md.j2` through `sc_render.render` into a Textual `Markdown` widget (id, severity icon, category, `file:line` refs, issue, required correction, filing `reviewer`). A per-reviewer pane needs QA-bead `metadata.reviewers`, which no bj sprint writes, so it is not in this sprint.
6. Icons (`icons.py`): the sanity PASS, FAIL and API_FAILURE glyphs and colours from the layout C table (`/Users/randlee/.config/atm/share/atm-dev/layout-c-icons/`, the codepoint and hex per entry); API_FAILURE is a different glyph from FAIL. Every agent name the two tabs print (the dev, each reviewer) is drawn by the existing `icon_for()` of phase bi, icon immediately left of the name (ANC-023), and the tabs' tests assert these cells: a sanity agent (sanity-jev, sanity-llm, the dev-sanity member) draws U+F01A6 in #E551BA whatever its harness or model (ANC-026, ANC-017); a qa agent (quality-mgr and each reviewer of a QA run) draws U+F029B, in #4A5AF8 while its run is active, #2EA043 after a PASS and #F85149 after a FAIL (ANC-021, ANC-017); every other agent, the dev included, draws its model icon chosen by lower-casing the roster model string and testing it with contains: haiku U+F0156 #FF6533, sonnet U+F0382 #FF784D, opus U+F06C4 #FF8C66, fable U+F0717 #FF9F80 for Claude agents (ANC-019); sol U+F05A8 #FFA60D, luna U+F0F65 #FFE066, terra U+F01E7 #2DE057, astra U+F0674 #FFE066 for Codex agents (ANC-020, ANC-024); no match gives sonnet for a claude-code agent and terra for a codex-cli agent (ANC-025). bj-4 adds no agent-icon rule and no agent glyph; the table above is the one `icons.py` already holds.
7. Dispatch read order (ANC-061): `runner.py` on every tick reads `bd ready` first and `atm task list` second, and assigns a sanity or qa bead only when `bd ready` listed it and the task list read afterwards holds no open (assigned or active) task with that bead id, and the bead is status open with no assignee; a closed task of that id (an earlier sanity round, ANC-057) does not block a same-id re-assign (lead ruling on ANC-061: only an open task means the hook already assigned it); a same-id assignment racing with the hook is an update/notify, not a second task row (atm-core #1619); a bead whose task the close hook already assigned is never assigned twice. This is atm-bd's half of ANC-052: the hook assigns the sanity task in its own run, and atm-bd assigns only the sanity bead the hook did not reach. The candidate filter stays a pure sanity/qa-stage filter in `dispatch.py`: atm-bd never assigns a dev or fix bead, the lead does, the dev starts its next queued task when the close hook closes its current one, and a QA fix bead goes to the dev the lead picks at the finding's difficulty (ANC-060), and every assign dispatch issues keeps running as the phase lead read from `.atm-bd/phase-<x>.toml` on that one subprocess, with atm-bd's notices still sent as `atm-bd@tool` (ANC-051, unchanged phase-bi behaviour).
8. Tests: ledger rows with and without the new fields; the runner read order and the no-second-assign case with injected sources (`test_runner.py`), the pure filter (`test_dispatch.py`); `API_FAILURE` kind rendering with its icon and reason; newest-first order; the quality tab's run-level rows and findings render from fixture beads; `qa-findings.md.j2` strict render with its example vars (`test_templates.py` already globs `templates/*.j2`, no edit there); `test_tabs.py` covers the two new panes; `test_icons.py` the new glyphs.

### Retry Policy
`jev_client.py` owns the sole retry policy (ANC-084): four total attempts maximum (three retries) for transport errors, HTTP 502, an API-busy answer and rate limiting; an oversized request is shortened (the existing `diff_pieces` split) and retried within the same attempt budget; only a request still too large after shortening is an API_FAILURE with that reason. This is a lead ruling on Rand's words (phase-bj planning 2026-10-18: "instead of editing context, failure is returned") and replaces the retired oversized-no-retry check. Injected HTTP responses and a controlled clock assert attempt count, elapsed coverage across attempts, eventual success, and API_FAILURE error without sleeps.
