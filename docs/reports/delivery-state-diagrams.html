Delivery State Machines

These panels visualize the Phase Y delivery-policy coordinator and the required event-family state machines so harness routing, companion-error behavior, and staged rebuild flows stay auditable.

Ack Reply

Ack legality, ack-state persistence, and delegated reply delivery.

Open panel

SSOT: docs/phase-Y/ack-reply.mmd

This machine validates the ack target, commits the ack transition first, then builds one reply delivery request and delegates the outward reply path to the approved new-message machine instead of embedding reply logic back into `ack`.

Notes

  • ack legality distinct from new-message
  • reply delegates to NewMessageStateMachine
  • observable ack-state commit required

Delivery Policy Coordinator

Central dispatcher for write-affecting mail events.

Open panel

SSOT: docs/phase-Y/delivery-policy-coordinator.mmd

This coordinator resolves event family and canonical roster harness, then dispatches into the required event-family state machine without letting command-local conditionals own delivery policy.

Notes

  • dispatcher only
  • no event legality inside coordinator
  • observable transitions required

Inbox Repair

Explicit staged rebuild for a Claude inbox repair request.

Open panel

SSOT: docs/phase-Y/inbox-repair.mmd

This machine is the approved bulk mailbox creation or rebuild path. It validates Claude harness ownership, loads a bounded repair projection, filters deleted messages, stages the rebuild, and publishes atomically.

Notes

  • explicit repair only
  • ClaudeCode harness only
  • bounded non-deleted history projection

Claude Harness New Message

New-message state machine for Claude Code harness delivery.

Open panel

SSOT: docs/phase-Y/new-message-claude.mmd

This machine persists SQLite first on the success path, allows Claude-only compatibility append after commit, and on SQLite failure still emits the original plus an `atm-system@` error companion with mirrored nudges.

Notes

  • harness gate: ClaudeCode only
  • sqlite failure emits original + error companion
  • append failure after sqlite success falls back to post-send-hook

Non-Claude Harness New Message

New-message state machine for non-Claude harness delivery.

Open panel

SSOT: docs/phase-Y/new-message-non-claude.mmd

This machine never appends JSONL. It persists SQLite on the success path, routes the original message through the non-Claude delivery path, and on SQLite failure still emits the original plus an `atm-system@` error companion through that same non-Claude path.

Notes

  • no JSONL append ever
  • harness gate: NonClaude only
  • sqlite failure emits original + error companion

Restore Inbox Rebuild

Restore-marker-scoped staged publish for inbox restore recovery.

Open panel

SSOT: docs/phase-Y/restore-inbox-rebuild.mmd

This machine stays distinct from normal repair because it is a privileged recovery path with restore-marker validation, staged restore output, and restore-specific publish semantics.

Notes

  • restore marker required
  • ClaudeCode harness only
  • staged restore publish

Thread Update

Add-details and supersede legality plus harness-dispatched delivery.

Open panel

SSOT: docs/phase-Y/thread-update.mmd

This machine is distinct from new-message delivery because it must prove parent existence, root existence, original-sender identity, and one-successor linearity before persisting or dispatching any outward effect.

Notes

  • modes: add-details, supersede
  • legality first
  • dispatch after sqlite commit
