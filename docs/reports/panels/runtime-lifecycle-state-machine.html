Daemon Runtime Lifecycle State Machine

Legal daemon runtime ownership transitions after bootstrap reaches a live daemon.

SSOT: docs/atm-daemon/runtime-lifecycle-state-machine.mmd

This machine models `RuntimeComposition::start()`, `RuntimeLifecycle`, and the fail-closed startup path in daemon composition. Every edge is a real event or guard in code, and every failure terminal is observable through a typed caller error from the active command.

Notes

  • explicit RuntimeLifecycle states only
  • startup failure rolls back to stopped
  • no direct Running to Stopped success path

Recovery And Visibility

Recovery Rules

  • If startup fails before Running, the active caller gets a typed runtime/startup error and doctor does not return a report.
  • If the daemon reaches Running, later command-specific or doctor-specific state machines own the next visible outcome.

Terminal Error Classes

  • StartupFailed is a caller-facing startup dependency error with rollback to Stopped.
  • Running is the success state that permits request serving.
  • StoppedAfterShutdown is the normal shutdown terminal.
