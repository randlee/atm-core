Reachable Daemon Request Outcome State Machine

Command and doctor outcomes after bootstrap has already reached a live daemon.

SSOT: docs/atm-daemon/reachable-daemon-request-outcome-state-machine.mmd

This machine models the current post-bootstrap split on `integrate/phase-Z`: doctor compares config and ATM roster when it can run, send requires an ATM roster member before harness resolution, and copied preexisting SQLite state may still fail schema initialization. These are reachable-daemon outcomes, not bootstrap outcomes.

Notes

  • daemon already reachable
  • state splits are command-visible
  • doctor visibility is explicit at each terminal

Recovery And Visibility

Recovery Rules

  • If a reachable-daemon command can identify the fix, return a typed caller error with recovery text.
  • If the issue is config or roster drift, doctor should report the mismatch and remediation.
  • If SQLite state cannot initialize, caller gets a typed SQLite error and doctor does not return a report.

Terminal Error Classes

  • DoctorHealthy and DoctorWarning are doctor report terminals.
  • SetupGuidanceError is a caller-facing roster/setup error that doctor should also explain.
  • SqliteStateError is a caller-facing SQLite/runtime error and doctor does not return a report.
