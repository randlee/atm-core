atm-core/announcements/v1.4.3

atm-core v1.4.3 Released 17 Aug 2026 Personas as of 21 Aug 2026

A smaller transport, templates you write once, and pip-installable agent tooling

Hand-written HTTP framing is gone, replaced by a minimal Tokio/Axum runtime. A message can be authored once as a durable template and fanned out. And the Python surface of ATM installs with pip for the first time.

Do not use v1.4.2

That tag predated a packaging fix: the isolated cargo publish build failed because the CLI embedded an OpenAPI file from outside the crate directory, so it was absent from the tarball. v1.4.3 republishes all 12 crates from a clean release line. The 11 crates already published at 1.4.2 stay on crates.io permanently. Use 1.4.3.

What you can do now

Write a message once, fan it out many times

A durable template catalog with render-on-read means a message is authored once and reused, instead of every send being a hand-built string. Typed search and read-only analyst queries give deterministic lookups into the mailbox, and atm compose wraps the catalog so a template-driven message is a first-class orchestration step. Roster management also gains atm teams remove-member, so a member leaves the roster without anyone touching the store.

atm compose --template <name> --var key=value
atm teams remove-member <TEAM> <MEMBER>

Embed a transport small enough to audit

The transport layer receives its biggest rewrite since the SQLite backbone: the minimal Tokio/Axum HTTP runtime (atm-http-runtime) replaces hand-written synchronous framing for both local and cross-host listeners. The legacy machinery it superseded (old HTTP framing, local and peer transport workers, resend/replay, and the obsolete cross-host subsystem) is deleted, leaving a daemon that is a clean local-IPC-only singleton with the same mailbox contract.

cargo install agent-team-mail
brew install randlee/tap/agent-team-mail

Give an agent ATM without a Rust toolchain

hermes-atm and atm-graft publish a full manylinux, musllinux, Windows and aarch64 wheel and sdist pipeline for CPython 3.11 through 3.14: the first PyPI publishing for the ATM Python surface. Agents get native atm_send/atm_read tooling and graft-based injection from pip. Identity still resolves from ATM_TEAM/ATM_IDENTITY, and the auto-start daemon singleton is unchanged.

pip install hermes-atm atm-graft

Keep the daemon lean and steerable

Daemon runtime session and pid observation converges into diagnostic-only heartbeat caching, trading aggressive runtime tracking for a leaner singleton that still reports health through atm doctor. atm-graft remains the out-of-band steering path, now pip-installable and easier to script into fleet operations.

pip install atm-graft
atm doctor

Give agent pipelines a typed hand-off

The template catalog plus typed search gives workflow authors a reliable, queryable message contract between graph nodes, so a multi-step pipeline passes messages deterministically. Cross-team addressing and pending-ack tracking, the reliability backbone this builds on, are unchanged.

Upgrading

brew upgrade randlee/tap/agent-team-mail
# or
cargo install agent-team-mail --force
# Python surface
pip install --upgrade hermes-atm atm-graft

Action needed

  • Do not install or pin v1.4.2; it is abandoned and its tarball is incomplete. Use v1.4.3.
  • The published crate set grows from 9 to 12: atm-error, atm-http-runtime and atm-template-sc-compose are new.
  • Local workarounds for the legacy peer-transport workers or resend/replay no longer apply: the daemon is local-IPC-only.

What comes next

v1.4.3 carries the full Phase AL/AM/AN feature set (originally authored for the abandoned 1.4.2) plus the recovery fix. With the Tokio runtime in place and legacy transport deleted, subsequent work turns to the PyPI production publish (currently on TestPyPI), Phase AI cross-host targets, and deeper analyst-query surfaces.
