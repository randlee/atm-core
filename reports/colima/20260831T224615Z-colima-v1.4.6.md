## AT3 — the one open item

AT3 (cross-host container↔Mac roundtrip) is SKIP in the container-only suite by
design: it needs the documented `--peer` wall exception (published 43102/2222 +
sshd, scope agreed with fenix@atm-dev). The dedicated run is staged: container
peer interface bound and advertising, mirrored `fx-at3` fixture rosters and
mutual fingerprint trust pins in place on both sides. One product behavior
found during wiring (not a release blocker): mTLS trust pins are built once at
daemon bootstrap (`MtlsPeerStreamAdapter::from_peer_config`, verified at
source, no reload path), so a trust entry added to a running daemon only takes
effect after a daemon restart. The host-side restart is coordinated via
fenix@atm-dev (`/daemon-switch`); AT3 will be appended to this report family
as its own paired file when the leg completes.
